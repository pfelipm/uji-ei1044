Encadenamiento de Comandos

Flujo de Datos vs. Flujo de Control

No todos los conectores son iguales

En PowerShell, es crucial diferenciar entre los operadores que mueven DATOS (la salida de un comando) y los que reaccionan al ÉXITO o ERROR de un comando. Son dos conceptos totalmente distintos.

|

La Tubería de Datos

⚙️➡️⚙️

¿Qué hace?

Coge los objetos de salida del comando de la izquierda y los usa como entrada para el comando de la derecha. Es una cinta transportadora de datos.

Ejemplo:

# Obtiene los objetos de proceso y los # envía a Sort-Object para ordenarlos. Get-Process | Sort-Object -Property CPU

&&

El Condicional de Éxito

✅➡️🏃‍♂️

¿Qué hace?

Ejecuta el comando de la derecha SÓLO SI el comando de la izquierda ha finalizado con éxito (sin errores).

Ejemplo:

# Si el ping funciona, entonces muestra el # mensaje de éxito. Test-Connection "google.com" -Quiet && Write-Host "Google responde"

||

El Condicional de Error

❌➡️🏃‍♂️

¿Qué hace?

Ejecuta el comando de la derecha SÓLO SI el comando de la izquierda ha fallado.

Ejemplo:

# Si no se encuentra el proceso, entonces # muestra el mensaje de error. Get-Process "proceso_falso" -ErrorAction SilentlyContinue || Write-Error "El proceso no existe"

La Solución Robusta: if y la variable $?

¿Y si necesitas hacer ambas cosas a la vez: entubar el resultado en caso de éxito y ejecutar otra acción en caso de error? Los operadores de encadenamiento se quedan cortos. Aquí es donde brilla la lógica condicional.

# 1. Ejecutamos el comando y guardamos su resultado en una variable. $proceso = Get-Process "pwsh" -ErrorAction SilentlyContinue # 2. Comprobamos el estado del ÚLTIMO comando con $? if ($?) { # ÉXITO: $? es $true. Ahora podemos usar la variable $proceso. Write-Host "Proceso encontrado. Entubando su nombre y ID..." -ForegroundColor Green $proceso | Select-Object Name, Id } else { # ERROR: $? es $false. La variable $proceso está vacía. Write-Error "No se pudo encontrar el proceso 'pwsh'." }

¡OJO! No confundir $? con $_

  • $?: Contiene el ESTADO (éxito/error) del último comando. Es un booleano ($true o $false).
  • $_: Contiene el OBJETO ACTUAL que está pasando por la tubería |. No sirve para este tipo de lógica condicional.

Tabla Resumen

Operador Función Principal ¿Transfiere Datos? ¿Reacciona a Éxito/Error?
| Conectar la salida de datos de un comando con la entrada de otro. SÍ (Es su único trabajo) No
&& Ejecutar el segundo comando solo si el primero tiene éxito. NO SÍ (Éxito)
|| Ejecutar el segundo comando solo si el primero falla. NO SÍ (Error)
