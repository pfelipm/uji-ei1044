Gestión de Errores

Creando Scripts a Prueba de Fallos

Entendiendo los Errores en PowerShell

No todos los errores son iguales. Para gestionarlos correctamente, primero hay que entender sus dos "sabores" principales.

Errores que NO detienen (Non-Terminating)

Son los más comunes. Muestran un mensaje de error en rojo, pero el script continúa su ejecución. Por ejemplo, si Get-ChildItem no encuentra un fichero.

Errores que SÍ detienen (Terminating)

Son errores graves que paran el script en seco. Por ejemplo, un error de sintaxis o intentar llamar a un comando que no existe.

El Método Moderno: try, catch y finally

Esta estructura es el estándar profesional para manejar errores de forma controlada. Te permite "intentar" ejecutar un código y tener un "plan B" si algo sale mal.

try { # Aquí va el código que podría fallar. # ¡IMPORTANTE! Para que 'catch' funcione con errores que no detienen, # hay que añadir -ErrorAction Stop al comando. Get-Content -Path "fichero_inexistente.txt" -ErrorAction Stop } catch { # Este bloque SÓLO se ejecuta si hay un error en el 'try'. Write-Error "No se pudo leer el fichero. Detalles: $($_.Exception.Message)" } finally { # (Opcional) Este bloque se ejecuta SIEMPRE, haya error o no. # Perfecto para tareas de limpieza (ej. cerrar conexiones). Write-Host "Operación de lectura finalizada." }

La Clave: -ErrorAction Stop

El bloque catch solo se activa con errores que detienen la ejecución. Usa -ErrorAction Stop en tus comandos dentro del try para forzar que cualquier error sea tratado como "grave" y active el catch.

La Regla General: $ErrorActionPreference

Esta variable automática define el comportamiento predeterminado para toda la sesión. Su valor por defecto es Continue (muestra el error y sigue). El parámetro -ErrorAction anula esta regla general para un comando específico.

Comparativa de Métodos de Gestión de Errores

if ($?) (El Verificador Básico)

Comprueba si el último comando tuvo éxito. Es simple y directo.

Ideal para: Lógicas simples de "si esto funcionó, haz lo siguiente".

try/catch (El Estándar Profesional - ¡Usa este!)

Permite manejar errores de forma precisa dentro de un bloque de código específico, ofreciendo control total sobre la excepción.

Ideal para: Prácticamente todos los scripts. Es la forma más robusta y legible.

trap {} (El Método Obsoleto)

Define un "capturador" de errores global para todo un script o función. Es menos preciso y su uso está desaconsejado en código moderno.

Ideal para: Entender scripts antiguos. Evitar en código nuevo.
