Panel central: elige tu batalla

🌐 Modelo de red abierta

¿Cuándo se usa?

Para sistemas con una fuente infinita de clientes. Llegan, se les sirve y se van.

Ejemplos: servidores web, APIs públicas, sistemas de streaming.

La receta (el algoritmo de resolución)

  1. 1
    Calcular utilizaciones (Uᵢ):
    Uᵢ = λ₀ × Dᵢ
  2. 2
    Calcular tiempos de respuesta por recurso (Rᵢ):
    Rᵢ = Sᵢ / (1 - Uᵢ)

    ¡Rᵢ se dispara cuando Uᵢ se acerca al 100%!

  3. 3
    Calcular tiempo de respuesta total (R):
    R = Σ (Vᵢ × Rᵢ)

💡 Ejemplo rápido: si llegan λ₀ = 2 trab/s a un disco con Dᵢ = 0,4 s (1 visita), su ocupación es Uᵢ = 0,8 (80 %) y su tiempo se multiplica por 5: Rᵢ = 0,4 / (1 - 0,8) = 2 s.

🔄 Modelo de red cerrada

¿Cuándo se usa?

Para sistemas con una población finita y constante de clientes (N) que alternan entre esperar la respuesta del servidor y un tiempo de reflexión (Z) antes de enviar su siguiente trabajo.

Ejemplos: sistemas de terminales interactivos, procesos batch con hilos fijos (donde Z = 0).

El atajo del administrador (límites)

En lugar de iterar con el , calculamos directamente el punto de colapso del sistema.

Concepto clave: el punto de saturación (N*)

Es el «número mágico» de usuarios concurrentes. Por encima de él, se forman colas permanentemente.

N* = (ΣDᵢ + Z) / Dₑ
  • ΣDᵢ: suma de demandas de todos los recursos (tiempo mínimo de respuesta sin colas).
  • Z (tiempo de reflexión): tiempo medio que el usuario «piensa» en su terminal antes de lanzar otra petición.
  • Dₑ: demanda del recurso cuello de botella (el de mayor Dᵢ).

💡 Ejemplo rápido: si la suma de demandas es ΣDᵢ = 1 s, el cuello de botella exige Dₑ = 0,5 s y los usuarios piensan Z = 9 s, el sistema saturará a partir de N* = (1 + 9) / 0,5 = 20 usuarios.

Redes cerradas · Resolución exacta

¿Qué es el algoritmo MVA?

MVA (Mean Value Analysis o análisis del valor medio) es el algoritmo clásico (Reiser y Lavenberg, 1980) para calcular con exactitud el tiempo de respuesta (R), la productividad (X₀) y las colas en una red cerrada con N usuarios.

🤔 ¿Por qué no podemos usar la receta directa de redes abiertas?

En una red abierta conocemos de entrada el caudal λ₀. Pero en una red cerrada existe un círculo vicioso: la productividad X₀ depende de cuánto tarden las peticiones (R), que a su vez depende de cuánta cola haya en cada recurso (Nᵢ), ¡que a su vez depende de X₀!

⚙️ ¿Cómo rompe MVA ese círculo? (Iteración de 1 a N)

Se apoya en una propiedad demostrada matemáticamente (teorema de llegada): cuando un trabajo llega a un recurso en un sistema con n usuarios, la cola que se encuentra delante es exactamente la cola media que había cuando el sistema tenía n - 1 usuarios. Partiendo del sistema vacío (Nᵢ(0) = 0), repite este bucle desde n = 1 hasta N:

  1. Tiempo de respuesta por visita en cada recurso: Rᵢ(n) = Sᵢ × [1 + Nᵢ(n - 1)]
  2. Tiempo total y productividad del sistema (ley de Little): R(n) = Σ [Vᵢ × Rᵢ(n)] y X₀(n) = n / [R(n) + Z]
  3. Nueva cola media en cada recurso (para la siguiente vuelta): Nᵢ(n) = X₀(n) × Vᵢ × Rᵢ(n)

🎯 ¿Por qué usamos el atajo de N* en pizarra? Si hay N = 50 usuarios, MVA obliga a dar 50 vueltas al bucle (algo ideal para que lo calcule al instante el simulador de la SPA 18, pero tedioso a mano). Con la fórmula de límites asintóticos (N*) averiguamos en una sola operación a partir de cuántos usuarios colapsará el sistema.
